# Public source publication policy

The public repository contains an application foundation under active migration. It is not the complete desktop application and has no public installer release.

## Source review

Every proposed source file must record its origin, authorship evidence and applicable license before inclusion. Classify original project code, third-party licensed material, vendor-derived material and unresolved provenance separately. Internal source hashes establish continuity; they do not establish ownership. A similarity scan or passing test is not redistribution permission.

Do not include vendor firmware images, extracted vendor executables, drivers, tuning data or copied proprietary reference implementations without specific redistribution authority. Independently implemented interoperability code needs its own provenance record. Preserve third-party notices and terms; a project license cannot replace them.

The six shared helpers have a dedicated source review and byte-pinned import receipt. The operator reports verbal Caddx approval for CRSF/MSP; preserve that provenance and distinguish it from a blanket vendor license.

## Private product boundary

The remaining Caddx-guidance gate concerns Service Mode and widget releases depending on it. Private Service Mode implementation, access/provisioning assets and dependent installation executors are not included in this source snapshot. Public interfaces do not authorize exporting those implementations.

## Intended permissions

The operator intends to permit personal, hobbyist development, educational and private professional use of original project code, with attribution. Resale, sublicensing and incorporation into third-party products are not intended permissions. Final source-available terms and the list of material they cover remain pending review; this policy is not a license grant. Third-party rights and permissions afforded by the hosting platform remain separate.

## Preview readiness

A developer preview announcement must identify the actual public commit and available functionality, state that the desktop application is still being migrated, and link the publication and licensing status. A downloadable application announcement additionally needs reviewed dependency boundaries, reproducible public packages and clean install/upgrade checks. No announcement or repository visibility change is authorized by this policy alone.
