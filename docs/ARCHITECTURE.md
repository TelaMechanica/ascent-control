# Product contract — migration draft

One shared application and configuration identity. A verified private application extension plus its actually loaded provider enables the upgraded product. Request fields, environment variables, edition stamps and hidden menus are insufficient. Receiver readiness/authorization remain separate operation-level checks.

Packages declare version, loader compatibility, application floor, kind, product dependency and stable configuration family. Reserved identities enforce minimum dependencies independently of manifest claims. The private mapping variant cannot install or execute on the base product. Variant upgrades keep the mapping family namespace; schema changes require reviewed migration. Dependency-breaking removal and ordinary downgrades are refused.

The module is a dependency/upgrade planner, not an arbitrary-code loader, authenticated publisher system, atomic installer or integration into the old application. Those implementation and verification tasks remain before a distributable product claim.
